# Вентиляция, отопление и инженерные системы — сайт-каталог представительства в Санкт-Петербурге

Многостраничный каталог: вентиляция с рекуперацией тепла, центральные пылесосы, радиаторы, конвекторы и инженерные системы для домов и квартир в Петербурге, Ленобласти и по всей России. Сайт написан на React, но каждая страница при сборке превращается в готовый HTML (хорошо для SEO: поисковик видит текст, заголовки и мета-теги без JavaScript), а в браузере React только «оживляет» её — меню, галереи и копирование контактов.

Формы заявки на сайте нет: внизу страниц блок «Контакты» (телефон, почта, Telegram, MAX) из `data/site.json` → `contacts`. Сервер с `POST /api/request` (заявка → Telegram) остался в `server/` на случай, если форма понадобится снова; тестовый сайт на Netlify — чистая статика из `dist/`.

## Быстрый старт

```bash
npm install
cp .env.example .env   # вписать BOT_TOKEN и CHAT_ID
npm run serve          # сборка в dist/ и сервер на http://localhost:3000
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Режим разработки (Vite) с мгновенным обновлением — без готового HTML и без сервера заявок |
| `npm run build` | Сборка: клиент (Vite) → серверный рендер → пререндер всех страниц в `dist/` + `sitemap.xml`, `robots.txt` |
| `npm start` | Сервер: раздаёт `dist/` (и `POST /api/request`, если форма вернётся; читает `.env`, если он есть) |
| `npm run serve` | `build` + `start` |
| `npm test` | Все тесты (Vitest): компоненты, гидратация, пререндер, сервер |
| `npm run lint` / `npm run format:check` | ESLint и Prettier |
| `npm run smoke` | Проверка в браузере (Playwright) после `npm run build`: все страницы на 1366, 834 и 390 px, скриншоты в `/tmp/blizzard-shots` |
| `npm run screens` | Скриншоты ключевых страниц на 11 ширинах (360–1920 px) и открытое меню на планшете и телефоне — в `/tmp/blizzard-screens` |

Нужен Node.js 22.12+. Для `npm run smoke` — Chromium для Playwright (`PLAYWRIGHT_BROWSERS_PATH`).

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота от @BotFather |
| `CHAT_ID` | Чат или группа, куда приходят заявки |
| `PORT` | Порт сервера, по умолчанию 3000 |
| `SITE_URL` | Адрес сайта для canonical, Open Graph и `sitemap.xml` (при сборке) |
| `TRUST_PROXY` | `1`, если сайт стоит за nginx — чтобы лимит заявок считал реальные IP |

Если `BOT_TOKEN` или `CHAT_ID` не заданы, сайт работает, а `POST /api/request` отвечает 503 (и это пишется в лог). Сейчас формы на сайте нет, так что для статики эти переменные не нужны.

## Как устроена сборка

1. `vite build` собирает клиент: `dist/assets/*.js` и один `*.css` (стили компонентов склеиваются в порядке подключения).
2. `vite build --ssr src/entry-server.jsx` собирает серверный рендер в `dist-server/`.
3. `scripts/prerender.js` для каждой страницы из `src/lib/routes.js` рендерит HTML (`react-dom/server`) и теги `<head>` (компонент `Head`: title, description, canonical, Open Graph, JSON-LD), вставляет их в шаблон `index.html` и пишет в `dist/<адрес>.html`. Там же — SVG-заглушки картинок, настоящие фото, `sitemap.xml` и `robots.txt`.
4. В браузере `src/main.jsx` вызывает `hydrateRoot`: разметка уже на месте, React только подключает обработчики. Расхождение HTML и клиента — ошибка (её ловят тест гидратации и `npm run smoke`).

Адреса страниц прежние: `/`, `/ventilation.html`, `/ventilation/l2.html`, `/dust-removal/v2.html`… Сервер отдаёт их и без `.html`. Ссылки между страницами — обычные `<a>`: каждая страница — отдельный готовый HTML, React Router только выбирает, какую страницу гидратировать.

```
src/
  main.jsx            — вход в браузере: гидратация готового HTML
  entry-server.jsx    — вход для сборки: HTML страницы, <head>, заглушки, sitemap
  App.jsx             — маршруты: страница из списка → её компонент
  components/         — у каждого компонента своя папка: .jsx, .css и тест рядом
    Header/           — шапка, выпадающие списки (NavDropdown), мобильное меню
    Footer/ Breadcrumbs/ Layout/ Button/ SectionTitle/ PageHero/ Specs/ StubText/

    VariantList/      — модели и бренды внутри категории (группы, галереи, папки-ссылки)
    Kinds/            — виды/типы внутри категории (сетка 3 → 2 → 1)
    CatalogImage/ HeatRecoveryDiagram/
    Placeholder/      — SVG-заглушка вместо фото (при сборке → /images/placeholders/*.svg)
    Head/             — теги <head> для пререндера
  pages/              — страницы: HomePage/, SectionPage/, CategoryPage/, AboutPage/,
                        ContactsPage/, LegalPage/ (политика обработки данных), NotFoundPage/
  lib/                — данные (content.js), список страниц (routes.js), картинки (images.js),
                        SEO (seo.js, seo-files.js), помощники для текста (text.js)
  styles/             — только глобальное: tokens.css (шрифты, цвета, контрольные точки), base.css, layout.css
scripts/
  prerender.js        — пререндер всех страниц, заглушек, sitemap.xml и robots.txt
  photos-plugin.js    — Vite-плагин: список фото из images/ и заглушки в режиме разработки
public/               — копируется как есть: шрифты Unbounded и Onest, favicon
images/               — сюда кладутся фото; список нужных файлов — images/README.md
server/
  index.js            — запуск сервера
  app.js              — Express: POST /api/request + раздача dist/ (/assets кешируется надолго)
  validate.js         — проверка заявки (согласие обязательно: consent === true)
  telegram.js         — отправка в Telegram Bot API
  rate-limit.js       — не больше 5 заявок за 10 минут с одного IP
tools/smoke.js        — проверка в браузере (Playwright); screens.js — скриншоты на всех ширинах
tools/optimize-images.py — WebP-копии фото в images/opt (запускать после добавления фото)
```

## Как добавить товар (категорию)

1. Откройте `data/catalog.json` и добавьте объект в `categories` нужного раздела:

   ```json
   {
     "slug": "recuperator-x",
     "title": "Название категории",
     "image": "vent-recuperator-x.jpg",
     "summary": "Одна-две фразы для карточки и meta description.",
     "text": ["Абзац описания.", "Ещё абзац."],
     "specs": [["Производство", "Германия"], ["Расход воздуха", "[ЗАГЛУШКА]"]]
   }
   ```

   Необязательно: `"gallery": [{ "image": "…jpg", "title": "…" }]` — дополнительные фото; `"variants": [{ "title", "image", "logo"?, "text": [], "specs": [] }]` — модели или бренды внутри категории (карточки «Модели в линейке» / «Производители», с логотипом — бренд); `specs` можно не указывать. Неизвестные данные пишите как `[ЗАГЛУШКА]` — на сайте они подсветятся жёлтым.
2. Добавьте имя картинки (`image`) в таблицу в `images/README.md` — тест проверяет, что все картинки описаны.
3. `npm test && npm run build` — появятся страница `/<раздел>/<slug>.html`, пункт в меню и подвале, карточка в разделе, строка в `sitemap.xml` и SVG-заглушка вместо фото.

Новая страница не требует правок в коде: список страниц (`src/lib/routes.js`) строится из каталога.

## Фото

Фото лежат в `images/` (их источник — фото клиента и сайты брендов, каждое описано в [images/README.md](images/README.md)); для сайта из них делаются WebP-копии: `python3 tools/optimize-images.py`. Если файла нет, при сборке вместо него появится SVG-заглушка с названием товара (компонент `Placeholder`). Чтобы поставить новое фото, положите файл с нужным именем в `images/` и пересоберите — список имён в [images/README.md](images/README.md). В режиме `npm run dev` фото подхватывается сразу.

## Дизайн-система

Идея: печатный немецкий технический каталог. Никаких градиентов, теней, «стеклянной» шапки,
скруглённых «таблеток» и клетчатых фонов. Всё держится на сетке, тонких линейках и типографике.
Токены лежат в `src/styles/tokens.css`.

| Что | Значение | Где используется |
| --- | --- | --- |
| Бумага / подложка | `--paper` #f2f0ea, `--surface` #faf9f5 | фон страницы, чередование секций |
| Фон под фото | `--photo` #ffffff | карточки и галерея товаров (фото сняты на белом) |
| Графит | `--ink` #17191b, `--ink-soft`, `--ink-faint` | текст, кнопки, чёрные линейки |
| Линии | `--line` (тонкая бежевая), `--line-strong` (чёрная) | чёрная — начало раздела, бежевая — строки |
| Воздух / тепло | `--accent` #23578a, `--warm` #c8541f | ссылки, схема рекуперации (синий — приток, оранжевый — вытяжка) |
| Шрифты | Golos Text (текст и заголовки), Plex Mono | моно — рубрики, цифры, артикулы, подписи |
| Углы | `--radius: 0` | |

Правила:

- **Начало раздела:** сверху чёрная линейка во всю ширину (`.section-head`), под ней рубрика моноширинным шрифтом (`.eyebrow`), затем заголовок. Вводный абзац на ноутбуке стоит справа.
- **Заголовки:** Golos Text 500 с плотным трекингом. Один цвет, без выделения слов цветом.
- **Списки категорий:** строки между линейками со стрелкой, как оглавление. Не «таблетки».
- **Перечни свойств:** «термин — пояснение» (`<dl>`), без нумерации 01–06.
- **Кнопки:** прямоугольные. Основная чёрная, вторая с чёрной рамкой. При наведении основная становится синей.
- **Цифры и артикулы:** моноширинным шрифтом (`.mono`, первая колонка таблицы моделей).

## Адаптивная вёрстка

Одна система контрольных точек для всех компонентов (описана в `src/styles/tokens.css`):

| Экран | Ширина | Что меняется |
| --- | --- | --- |
| Телефон | ≤ 600px | Логотип, круглая кнопка звонка и «Меню»; всё в одну колонку; таблица моделей — карточками; у схемы в первом экране — легенда |
| Планшет | 601–1024px | Меню в кнопке, рядом номер телефона; карточки и объекты в 2 колонки, факты 2 × 2, подвал в 2 колонки |
| Ноутбук | 1025–1439px | Категории в 3 колонки, объекты в 4; фото и текст категории рядом. Полное меню из шести разделов и верхняя строка «Объекты · О компании · Контакты · телефон» — с 1280px, до 1279px меню в кнопке |
| Широкий | ≥ 1440px | Контейнер шире (1320px) |

Между точками заголовки, поля и отступы секций меняются плавно (`clamp()`). Эффекты наведения — только на устройствах с мышью (`hover: hover`), поля учитывают «чёлку» (`safe-area-inset`).

## Проверка качества

- ESLint (с правилами React и хуков) + Prettier, как в моих других проектах; без однобуквенных имён.
- CI в GitHub Actions: Prettier → ESLint → тесты → сборка.
- Тесты компонентов (Vitest + Testing Library): меню с клавиатуры (Enter, ↓/↑, Esc, уход фокуса), мобильное меню, блок контактов (ссылки, копирование почты и номера MAX), страница категории выводит все модели, хлебные крошки, подвал, таблица моделей.
- Тест гидратации: готовый HTML каждой из 41 страницы оживляется без единого предупреждения React.
- Тесты пререндера: все страницы созданы с правильным title, у каждой description, canonical, Open Graph и один h1, все внутренние ссылки и якоря рабочие, у картинок есть alt, sitemap полный.
- Тесты сервера: валидация, обязательное согласие, отправка в Telegram (подменена), 503 без переменных, 502 при ошибке Telegram, лимит 429, телефон не попадает в логи, раздача страниц с `.html` и без.
- `npm run smoke`: в Chromium все страницы на 1366, 834 и 390 px — 0 ошибок и предупреждений в консоли (в том числе о гидратации), нет горизонтальной прокрутки, нет битых ссылок и картинок; после гидратации работают выпадающие списки, мобильное меню и копирование почты из блока контактов.
- Доступность: alt у картинок, видимый фокус, меню с клавиатуры, ссылка «Перейти к содержанию», `prefers-reduced-motion`.
