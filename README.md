# Blizzard Lufttechnik — сайт-каталог представительства в Санкт-Петербурге

Статический многостраничный каталог: вентиляция с рекуперацией тепла и центральные пылесосы BLIZZARD lufttechnik для домов и квартир в Петербурге и Ленобласти. Страницы собираются из JSON в готовый HTML (хорошо для SEO, без отрисовки на клиенте), заявки с формы уходят в Telegram.

## Быстрый старт

```bash
npm install
cp .env.example .env   # вписать BOT_TOKEN и CHAT_ID
npm run dev            # сборка в dist/ и сервер на http://localhost:3000
```

| Команда | Что делает |
| --- | --- |
| `npm run build` | Собирает сайт в `dist/` |
| `npm run dev` | Сборка + сервер (читает `.env`, если он есть) |
| `npm start` | Только сервер (раздаёт `dist/` и принимает заявки) |
| `npm test` | Тесты сборки и сервера (`node:test`) |
| `npm run lint` / `npm run format:check` | ESLint и Prettier |
| `npm run screenshots` | Проверка в браузере (Playwright): все страницы на 1366 и 390 px, ошибки консоли, горизонтальная прокрутка, скриншоты в `/tmp/blizzard-shots` |

Нужен Node.js 22.12+. Для `npm run screenshots` — Chromium для Playwright (`PLAYWRIGHT_BROWSERS_PATH`).

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота от @BotFather |
| `CHAT_ID` | Чат или группа, куда приходят заявки |
| `PORT` | Порт сервера, по умолчанию 3000 |
| `SITE_URL` | Адрес сайта для canonical, Open Graph и `sitemap.xml` (при сборке) |
| `TRUST_PROXY` | `1`, если сайт стоит за nginx — чтобы лимит заявок считал реальные IP |

Если `BOT_TOKEN` или `CHAT_ID` не заданы, сайт работает, а форма получает ответ 503 (и это пишется в лог).

## Структура

```
data/
  catalog.json        — весь каталог: разделы → категории → title, slug, image, text, specs, models
  site.json           — компания, контакты, офисы, «почему Blizzard», объекты
scripts/
  build.js            — сборка: шаблоны + данные → dist/
  lib/                — экранирование, заглушки картинок, список страниц, sitemap/robots
  templates/          — шаблоны страниц на template literals (шапка, подвал, главная, раздел, категория…)
public/
  styles/             — CSS по блокам, при сборке склеиваются в один styles/site.css
  scripts/            — меню (выпадающие списки, мобильное меню) и отправка формы
  fonts/              — Unbounded (заголовки) и Onest (текст)
images/               — сюда кладутся фото; список нужных файлов — images/README.md
server/
  index.js            — запуск сервера
  app.js              — Express: POST /api/request + раздача dist/
  validate.js         — проверка заявки (согласие обязательно: consent === true)
  telegram.js         — отправка в Telegram Bot API
  rate-limit.js       — не больше 5 заявок за 10 минут с одного IP
test/                 — тесты сборки и сервера
tools/screenshots.js  — проверка в браузере
```

## Страницы (27)

- Главная, «Вентиляция», «Пылеудаление»
- 9 категорий вентиляции (`/ventilation/l2.html`, `/ventilation/r2.html`…) и 9 категорий пылеудаления (`/dust-removal/v1.html`…)
- Объекты, О компании, Контакты
- Политика обработки персональных данных, Согласие на обработку (шаблоны с жёлтой плашкой)
- 404

## Как поменять каталог

Всё содержимое — в `data/catalog.json`. Добавили категорию → `npm run build` → появилась страница, пункт меню, карточка в разделе и строка в `sitemap.xml`. Таблица моделей — это `models.columns` и `models.rows`.

## Фото

Фото с сайта производителя пока не используем — ждём разрешения клиента. Вместо них при сборке генерируются SVG-заглушки с названием товара. Чтобы поставить настоящее фото, положите файл с нужным именем в `images/` и пересоберите — список имён в [images/README.md](images/README.md).

## Что ещё нужно от клиента (заглушки)

На сайте такие места подсвечены жёлтым: `[ЗАГЛУШКА]` и `[РЕКВИЗИТЫ ПРЕДСТАВИТЕЛЬСТВА]`.

- Адрес офиса в Санкт-Петербурге.
- Реквизиты представительства (наименование, ИНН, ОГРН, адрес) — для подвала и документов.
- Технические данные моделей: L2, V1/V2/V3, профессиональные системы.
- Материал и поставка плоских воздуховодов R2, перечень фитингов.
- Число отводов у коллекторов 808–216 V, артикулы теплозащитной серии.
- Соответствие артикулов акустической серии диаметрам (сейчас — в порядке, как на сайте производителя).
- Модели диффузоров, состав аксессуаров, расходников и клапанов вентиляции.
- Цвета пневморозеток и пневмосовок, длины шлангов Wally-flex и Vroom, артикулы аксессуаров пылеудаления.
- Все фотографии (см. `images/README.md`) и адрес сайта (`SITE_URL`).
- Срок хранения данных и дата редакции в документах; проверка юристом требований о локализации и трансграничной передаче (заявки уходят через Telegram).

## Проверка качества

- ESLint + Prettier, те же правила, что в других моих проектах; без однобуквенных имён.
- CI в GitHub Actions: Prettier → ESLint → сборка → тесты.
- Тесты сборки: все страницы созданы, у каждой title/description/canonical/OG и один h1, все внутренние ссылки и якоря рабочие, у картинок есть alt, sitemap полный.
- Тесты сервера: валидация, обязательное согласие, отправка в Telegram (подменена), 503 без переменных, 502 при ошибке Telegram, лимит 429, телефон не попадает в логи.
- Доступность: alt у картинок, видимый фокус, меню с клавиатуры (Enter, стрелки, Esc), ссылка «Перейти к содержанию», `prefers-reduced-motion`.
